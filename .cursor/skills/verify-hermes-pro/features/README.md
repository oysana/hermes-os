# Hermes Pro verification map

The primary user surface is H/S/Y in Telegram, with native CLI and personal Telegram/WhatsApp intake. This map starts with the existing code interfaces. A successful source recipe proves only its named contract; model behavior and natural delivery need their own matching acceptance.

Read `../SKILL.md` for launch, admission, evidence and cleanup. Use one owned evidence directory per run. Every command below runs from the canonical Hermes Pro root unless a recipe says otherwise. Preserve original failures and source selectors.

- [Recall and tools](recall-and-tools.md) covers search-engine behavior plus H/S/Y × CLI/Telegram tool visibility.
- [Personal addressing](personal-addressing.md) covers common lexical cases, native mention metadata and service readiness. Natural group delivery remains a distinct entry point.

For a new feature add its user entry points, actual drive command, literal expected result, isolation and material limits. Report any unexercised entry point as unverified; one convenient route does not qualify the rest.
