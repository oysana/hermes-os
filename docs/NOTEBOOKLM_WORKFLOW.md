# Веди NotebookLM тематическими отчётами

Используй существующий notebook 447d7092-2c53-44af-b391-6d33d6d09c08 для Personal AI и сохранённого Factory AI знания. Текущий статус находится в shared/STATUS.md. Рабочий лимит этой библиотеки составляет 300 источников по указанию владельца. [Google описывает разные лимиты для разных планов](https://support.google.com/gemininotebook/answer/16213268?hl=en), поэтому доступную ёмкость проверяй перед загрузкой.

## Добавляй полезное знание целыми темами

1. Прочитай текущий отчёт темы и проверь живой список Sources.
2. Собери новые материалы в завершённую смысловую единицу. Напиши полный самостоятельный разбор. Объясни механизм, полезные выводы, применение к Hermes, ошибки, ограничения и незакрытые вопросы. Отдели факт источника от собственного вывода.
3. Сохрани исходные URLs, название, дату или commit, качество чтения и контекст доказательства. Для удаляемого источника сохрани его source ID и полный доступный indexed text. Мультимедиа учитывай отдельно от текста.
4. Обнови полный отчёт темы. Мелкие ссылки и отчёты каждого промежуточного checkpoint не превращай в отдельные Sources. Локальные журналы и исходные receipts остаются в .artifacts.
5. Загрузи новую полную редакцию через MCP в тот же notebook. Сохрани source ID до следующего действия. При неизвестном исходе сначала сверяй ID и title, чтобы не создавать дубли.
6. Прочитай replacement обратно целиком. Подготовленный literal payload должен полностью присутствовать в source_get_content. Обёртка провайдера может отличаться. Сокращённый preview, похожий summary и нормализованное сравнение отдельно не доказывают сохранность текста.
   Для точного сохранения Markdown передавай literal payload внутри внешнего code fence, который длиннее любого fence в payload. Сохраняй payload и envelope отдельно с hashes. Сравнивай полный payload после обратного чтения. Провайдер может разобрать незакрытый в envelope Markdown, изменить заголовки, таблицы и ссылки. При таком расхождении сохрани отказ и не удаляй старый источник. Исправленная редакция должна сохранить полные indexed texts покрываемых источников, включая промежуточный импорт, если его удаляешь.
7. После проверенного покрытия удали отдельные заменённые Sources и прежнюю редакцию отчёта, если её уникальное содержание сохранено. Разрешение владельца относится к таким заменённым и лишним источникам. Для единственного непокрытого оригинала его недостаточно.
8. Сверь полный набор оставшихся IDs. Добавь запись об импорте в TRANSFER-LEDGER.jsonl и запись о замене в SOURCE-MIGRATIONS.jsonl. Исторический ledger не переписывай. Активный набор вычисляется как импортированные IDs за вычетом подтверждённых удалений.

## Перед удалением проверь каждую строку mapping

Удаление разрешено только когда одновременно выполнены условия:

- Указан точный notebook и прежний source ID из текущего списка.
- Сохранена проверенная recovery копия его доступного текста и metadata.
- Указаны replacement ID, точный payload и hash.
- Полный прежний indexed text и исходный URL присутствуют в replacement.
- Exact payload подтверждён обратным чтением MCP.
- В mapping нет других source IDs. Оригинальные PDF, видео и неподтверждённые материалы требуют отдельной проверки.

При частичном delete не повторяй весь запрос вслепую. Сначала прочитай текущие Sources. Удалённые IDs запиши с подтверждением отсутствия. Работай только с ещё присутствующими разрешёнными IDs. Удалённый source ID нельзя восстановить тем же ID, поэтому прежние source-specific citations становятся историческими. Карта замен должна быть доступна облачному читателю внутри NotebookLM.
