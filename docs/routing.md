# Маршрутизация задач

Путь сообщения до результата.

## Вход: Telegram

- Один шлюз: systemd user `hermes-gateway.service`
  (`~/.hermes/hermes-agent/.hermes/bin/hermes gateway run`, `Restart=always`,
  reload = `kill -USR1 $MAINPID`, рестарт только при зависании).
- Один чат владельца, разбитый на топики (`dm_topics` в `~/.hermes/config.yaml`):
  «Главное» 9265, «Уведомления» 9267 (home_channel), «OyVoice» 9272,
  «OyMessage» 9274, «AiPay» 9276, «OyKaspi» 16840.
- У проектных топиков привязан навык (`skill:` в конфиге) — сообщение в
  топике OyVoice поднимает контекст проекта.
- Личные сообщения Y приходят через intake в `~/.hermes/shared/communications/`
  (tg-personal, wa-read, addressing, transcribe); WhatsApp — сервис
  `hermes-whatsapp-reader.service`.

## Внешний цикл: H

- H ведёт диалог, держит цель и решает, что делать. Сам код он почти не
  пишет — работу отдаёт во внутренний цикл.
- Решения вида «да/нет» или «выбрать одно» идут в `gemini-decision-1`
  через `~/.agents/lib/decisions.py`. Это единственная decision-модель.

## Внутренний цикл: T3

- H вызывает T3 только через официальный MCP-коннектор (`mcp_servers.t3`,
  инструменты `t3_*`). Процедура — навык
  `~/.hermes/skills/t3-work-bridge/SKILL.md`.
- Выбор места (seat) по работе — таблица в том же навыке: Devin SWE-2
  основной исполнитель, Codex Sol 6.2 — самый сильный судья, Codex Terra
  6.1 — аккуратная ограниченная работа, Gemini 3.8 Flash (Antigravity) и
  бесплатные OpenCode — быстрые read-only задачи.
- Работник получает worktree (`~/.t3/worktrees/<repo>/...`), свою ветку и
  бриф. Ожидание результата — фоновым `delegate_task`/watchers
  (`t3-tick`, `t3-stuck-watch`, `kanban-watch` в cron), никогда
  собственным ходом H.
- Квота/ошибка провайдера — стоп до восстановления (`quota-breaker`),
  молча не переключаться на другое место.

## Возврат результата

- Работник отчитывается в T3-тред; H принимает итог через мост, проверяет
  доказательство (артефакт/PR/вывод команды) и докладывает владельцу
  в его топик.
- Синтетический проход не закрывает реальную просьбу: проверка идёт через
  живой путь (вебхук или сообщение в топике), а не вызовом T3 напрямую.

## Что ещё ездит по этой дороге

- cron-задачи профилей поднимают ходы H/Y/S/J по расписанию (см.
  `docs/schedules.md`) — отчёты, вотчеры, напоминания.
- Канбан-карточки и цели живут внутри Hermes/T3; `kanban-watch` следит за
  доставкой результатов из T3-тредов.
